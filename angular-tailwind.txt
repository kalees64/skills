# Enterprise Frontend Architecture & Design Standard

This skill defines the mandatory standards for building production-grade SaaS interfaces using **Angular v19+**, **Tailwind CSS v4**, and **modern native CSS** for high-scale environments (millions to billions of users).

The objective is to deliver:

- Scalable architecture
- Long-term maintainability
- Performance at scale
- Accessibility compliance
- Test-driven reliability
- Distinct, brand-defining design quality

Every implementation must meet enterprise engineering standards.

---

# 1. NON-NEGOTIABLE ENGINEERING REQUIREMENTS

## 1.1 Framework & Platform Standard

- Framework: **Angular v19+**
- Language: **TypeScript (strict mode)**
- Component Model: **Standalone Components** (NgModules are forbidden in new code)
- Rendering Strategy: SSR via `@angular/ssr` (default), SSG, or CSR based on route needs
- State Management: **Angular Signals** (primary), **NgRx Signal Store** for complex global state
- Styling: **Tailwind CSS v4** + **native CSS** (SCSS is no longer required)
- No alternative frameworks

---

## 1.2 Architectural Discipline

All implementations must follow SOLID principles and clear separation of concerns.

Folder structure:
```
/core               ← app config, guards, interceptors, singleton services
/shared             ← reusable standalone components, pipes, directives
/features           ← lazy-loaded feature folders
/models             ← TypeScript interfaces and types
/services           ← HTTP and business logic services
/utils              ← pure utility functions
/styles             ← global CSS, Tailwind theme config, CSS custom properties
/__tests__          ← unit and integration tests
```

Requirements:

- All components must be **Standalone**
- No business logic in presentational components
- No direct HTTP calls in UI components
- All HTTP calls go through dedicated Angular Services
- Use `inject()` function — never constructor injection
- Lazy-load all feature routes via `loadComponent` / `loadChildren`

## 1.3 Angular v19+ Specific APIs (MANDATORY)

### Standalone Components
```typescript
@Component({
  selector: 'app-user-card',
  standalone: true,
  imports: [RouterLink],
  templateUrl: './user-card.component.html',
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class UserCardComponent {}
```

### Application Bootstrap
```typescript
// main.ts
bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes, withViewTransitions()),
    provideHttpClient(withFetch(), withInterceptors([authInterceptor])),
    provideAnimationsAsync(),
    provideClientHydration(withEventReplay()),
  ]
});
```

### `inject()` — Dependency Injection
```typescript
// ✅ CORRECT
export class ProductCardComponent {
  private productService = inject(ProductService);
  private router = inject(Router);
}

// ❌ WRONG — never use constructor injection
constructor(private productService: ProductService) {}
```

### Linked Signals — `linkedSignal()` (Angular v19+)
```typescript
import { linkedSignal } from '@angular/core';

// Linked signal automatically resets when source changes
const selectedIndex = linkedSignal(() => items().length > 0 ? 0 : -1);
```

### Resource API — `resource()` (Angular v19+)
```typescript
import { resource } from '@angular/core';

export class UserProfileComponent {
  userId = input.required<string>();

  userResource = resource({
    request: () => ({ id: this.userId() }),
    loader: ({ request }) => fetch(`/api/users/${request.id}`)
      .then(res => res.json())
  });

  // userResource.value()   → signal with data
  // userResource.isLoading() → loading state signal
  // userResource.error()   → error signal
}
```

### `httpResource()` — HTTP Resource (Angular v19.2+)
```typescript
import { httpResource } from '@angular/common/http';

export class ProductListComponent {
  categoryId = input.required<string>();

  products = httpResource<Product[]>(
    () => `/api/products?category=${this.categoryId()}`
  );

  // products.value()      → Product[] | undefined
  // products.isLoading()  → boolean signal
  // products.error()      → unknown signal
}
```

### Effect with Cleanup — `effect()` (Angular v19+)
```typescript
effect((onCleanup) => {
  const subscription = someObservable$.subscribe();
  onCleanup(() => subscription.unsubscribe());
});
```

### `afterRenderEffect()` — DOM-safe effects (Angular v19+)
```typescript
import { afterRenderEffect } from '@angular/core';

afterRenderEffect(() => {
  // Runs after every render — safe for DOM measurements
  console.log('DOM updated');
});
```

### View Transitions API (Angular v19+)
```typescript
// In router config
provideRouter(routes, withViewTransitions({
  onViewTransitionCreated: ({ transition }) => {
    // Hook into native View Transitions API
  }
}))
```
```css
/* In global CSS */
::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 300ms;
}
```

## 1.4 Signals — Complete Reference
```typescript
import {
  signal, computed, effect, linkedSignal,
  input, output, model,
  toSignal, toObservable,
  resource, httpResource
} from '@angular/core';

// Writable signal
const count = signal(0);
count.set(5);
count.update(v => v + 1);

// Computed (read-only derived)
const doubled = computed(() => count() * 2);

// Linked signal (resets reactively)
const resetOnChange = linkedSignal(() => sourceSignal());

// Signal input (replaces @Input)
name = input.required<string>();
variant = input<'sm' | 'lg'>('sm');

// Signal output (replaces @Output + EventEmitter)
clicked = output<void>();

// Two-way model (replaces @Output with ngModel pattern)
value = model<number>(0);

// RxJS interop
const users = toSignal(users$, { initialValue: [] });
const count$ = toObservable(countSignal);
```

# 2. MODERN TEMPLATE CONTROL FLOW (MANDATORY)

Never use `*ngIf`, `*ngFor`, `*ngSwitch`, or `[ngSwitch]` in any new code.

## 2.1 @if / @else if / @else
```html
@if (user.isAdmin) {
  <app-admin-panel />
} @else if (user.isModerator) {
  <app-moderator-panel />
} @else {
  <app-user-panel />
}
```

## 2.2 @for / track / @empty
```html
@for (item of items(); track item.id) {
  <app-item-card [item]="item" />
} @empty {
  <p class="text-neutral-400 text-sm">No items found.</p>
}
```

## 2.3 @switch / @case / @default
```html
@switch (status()) {
  @case ('active') { <app-active-badge /> }
  @case ('inactive') { <app-inactive-badge /> }
  @default { <app-unknown-badge /> }
}
```

## 2.4 @let — Template Variables
```html
@let fullName = user.firstName + ' ' + user.lastName;
@let total = cart().items.length;

<h2 class="text-xl font-semibold">{{ fullName }}</h2>
<span class="badge">{{ total }} items</span>

@if (total > 0) {
  <app-checkout-button [label]="fullName" />
}
```

## 2.5 @defer — Deferred Rendering
```html
@defer (on viewport; prefetch on idle) {
  <app-analytics-chart />
} @placeholder {
  <div class="h-48 rounded-xl bg-neutral-100 animate-pulse" />
} @loading (minimum 300ms) {
  <app-spinner />
} @error {
  <app-error-state message="Failed to load chart." />
}
```

Defer triggers: `idle`, `viewport`, `interaction`, `hover`, `immediate`, `timer(Xms)`, `when condition`

# 3. TAILWIND CSS V4 — MANDATORY STANDARDS

Tailwind CSS v4 introduces a **CSS-first configuration system**. There is no `tailwind.config.js` — all configuration is done in CSS using `@theme`.

---

## 3.1 Installation & Setup (Angular v19 + Tailwind v4)
```bash
npm install tailwindcss @tailwindcss/vite
```

Vite plugin setup (Angular uses Vite-based builder in v19):
```typescript
// vite.config.ts
import tailwindcss from '@tailwindcss/vite';

export default {
  plugins: [tailwindcss()]
};
```

Global CSS entry:
```css
/* styles/global.css */
@import "tailwindcss";
```

No `tailwind.config.js`. No `@tailwind base/components/utilities` directives. Just `@import "tailwindcss"`.

# 6. MANDATORY UNIT TESTING

## 6.1 Required Stack

- **Jest** + **Angular Testing Library**
- `provideHttpClientTesting()` for HTTP services
- `TestBed` with standalone component imports

## 6.2 Coverage Requirements

Test: component rendering, signal input/output/model behavior, `@if`/`@for`/`@switch` branches, user interactions, `resource()` / `httpResource()` loading and error states, service logic, guards, interceptors, pipes, and directives.

Target: **80%+ meaningful coverage** using the AAA pattern.

---

# 7. SCALABILITY MINDSET (BILLION-USER STANDARD)

Angular v19+ performance requirements:

- Standalone components everywhere — no NgModules
- `OnPush` change detection on all components
- Signals for all reactive state — RxJS only for streams
- `httpResource()` for all data fetching where appropriate
- `@defer` for heavy and below-the-fold UI
- Lazy loading via `loadComponent` / `loadChildren`
- `provideHttpClient(withFetch())` — native Fetch API
- `provideClientHydration(withEventReplay())` for SSR
- `withViewTransitions()` for native page transitions
- CSS Container Queries for intrinsically responsive UI
- Tailwind v4 CSS-first config — zero runtime overhead

---

# 8. STRICTLY PROHIBITED

- `*ngIf`, `*ngFor`, `*ngSwitch` in any new code
- `@Input()` / `@Output()` decorators — use `input()`, `output()`, `model()`
- Constructor-based dependency injection — use `inject()`
- NgModules in new features
- `tailwind.config.js` — all config goes in CSS `@theme`
- `@tailwind base/components/utilities` directives — use `@import "tailwindcss"`
- SCSS where native CSS or Tailwind v4 suffices
- `any` TypeScript type
- Business logic in component templates
- Direct HTTP calls in components — use services or `httpResource()`
- Missing `track` in `@for` blocks
- Observable memory leaks without `takeUntilDestroyed()` or `async` pipe
- Generic AI aesthetics and cookie-cutter layouts
- Untested components, services, pipes, and directives
- `console.log` in production code
- Non-accessible interactive elements

---

# 9. REQUIRED OUTPUT STRUCTURE

Every implementation must include:

1. Angular v19+ standalone component folder structure
2. Typed components with `OnPush` + `input()` / `output()` / `model()`
3. Services with `inject()` and `httpResource()` / `resource()`
4. Signals for all reactive state

A scalable Angular v19+ SaaS interface must be:

Predictable. Maintainable. Accessible. Testable. Distinct. Production-ready.

# Important Rules (MUST FOLLOW FOR EACH IMPLEMENTATION)

1. Before writing any code, describe your approach and wait for approval.
2. If requirements are ambiguous, ask clarifying questions before writing any code.
3. After finishing any code, list edge cases and suggest test cases.
4. If a task requires changes to more than 3 files, break it into smaller tasks first.
5. When there is a bug, write a reproducing test first, then fix until it passes.
6. Always use `@if`, `@for`, `@switch`, `@let`, `@defer` — never structural directives.
7. Always use `input()`, `output()`, `model()` — never `@Input()` / `@Output()`.
8. Always use `inject()` — never constructor injection.
9. Always use `resource()` or `httpResource()` for async data — no manual subscribe in components.
10. Always define design tokens in `@theme` — never hardcode values.
11. Always use native CSS nesting, container queries, and logical properties.
12. Always use `OnPush` change detection on all components.
13. Always handle Observable cleanup with `takeUntilDestroyed()` or `async` pipe.
14. Always write unit tests for every component, service, pipe, and directive.
15. Maximum 500 lines per component file.
16. Always use semantic HTML with unique IDs and ARIA attributes.
17. Always provide loading and error state UI per feature route.
18. Always respect `prefers-reduced-motion` in CSS animations.
